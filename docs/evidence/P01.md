## Resource and lifecycle source audit (2026-10-28)

A read-only Terra Medium audit, followed by parent source inspection, identified
two constraints for the next implementation. These are source findings, not new
runtime privacy or lifecycle acceptance:

- `servo-net` 0.7.0 `fetch/methods.rs` invokes the request interceptor before
  scheme dispatch, including non-HTTP fetches. It does so even if an earlier
  CSP check has already selected an error response. A callback observed under
  the strict CSP therefore cannot independently prove delegate enforcement.
  The next private synthetic probe needs isolated resource-only CSP relaxation,
  actual cancellation, negative observations and working positive controls.
  The interceptor exposes `request.url()` rather than dispatch's `current_url()`;
  verify redirect-target identity before ever allowing an initial remote URL.
  Current policy denies all initial HTTP loads, so no redirect escape is claimed.
- `servo` 0.7.0 `servo.rs:906` calls `initialize_options` on construction;
  `servo-config` 0.7.0 `opts.rs:279` uses `OnceLock::set(...).expect(...)`.
  `mozjs` 0.26.4 `src/rust.rs:204` rejects `EngineState::ShutDown`. The engine
  cannot simply be dropped and reconstructed in the same process. Servo's
  `WebViewInner::drop` does close a webview and remove its painter; upstream's
  `tests/webview.rs` exercises last-webview painter removal. Repeated webview/
  context release on one retained engine is the next minimal lifecycle probe,
  but it does not establish complete browser release while headless.

No public mail loader, CID support, hidden background engine policy or helper
process was introduced. Privacy and full lifecycle PLAN rows remain open.

## Scrolling and scale review correction

The adapter follows the pinned Iced `widget/src/scrollable.rs` policy of 60
logical pixels per wheel line, multiplies line deltas by the current scale, and
sends `DeltaPixel` to Servo. `servo-paint 0.7.0`'s
`webview_renderer.rs` default scroll uses the delta directly as device pixels,
regardless of mode. Pixel deltas are forwarded unchanged; normalized deltas must
be finite and no larger than 2048 physical pixels per axis. The public scale
setter enforces the same 1/2048..=2048 bounds as the app. The pinned Iced
mouse-area publishes the same wheel input twice, so each delivery is halved.
The window-open event now supplies initial logical geometry even when scale is 1.

The pinned winit conversion forwards `PixelDelta` directly, whereas the separate
Wayland `iced/winit/src/platform_specific/wayland/conversion.rs`

sources' `AxisScroll.absolute` to pixels without scaling. Consequently unchanged
pixel deltas preserve each backend's supplied value; physical equivalence for
Wayland touchpad input remains unproven. The same pinned `sctk_event.rs`
`SurfaceScaleFactorChanged` arm only updates `window_manager` state and does not
publish an application event. A bounded upstream fix would expose that change as
a standard application window event so the app can query scale; a scale-only
