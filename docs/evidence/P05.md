# P05 — Public-client OAuth and encrypted refresh prototype

P05 remains **incomplete**. Native browser authorization and shared IMAP/SMTP
credentials now have synthetic protocol and desktop evidence. No actual Google,
iCloud or institutional account has been authorized, and no real mail was sent.
Production registration, provider policies, real portals and Flatpak are separate
acceptance steps. The P07 release package at `091df66` predates this OAuth work.

## Implemented boundaries

- `oauth2 = 5.0.0` owns public-client authorization-code exchange, random CSRF state,
  S256 PKCE, token response types, refresh and typed grant errors. Its timing-resistant
  secret comparison feature checks callbacks. No manually constructed token JSON,
  embedded login form, borrowed app ID or client secret is shipped.
- Reqwest 0.12.28 provides HTTPS with native/explicit CA roots and normal certificate
  validation. Redirects are disabled. A small implementation of OAuth2's standard
  async HTTP interface retains at most 64 KiB of response body and discards provider
  diagnostics. Preparation/token operations have 30-second limits; connection setup
  is limited to ten seconds. This is not proof of a 64-KiB total transport allocation.
- Hyper 1.12.0, hyper-util 0.1.21 and http-body-util 0.1.5 provide the short-lived
  callback server, rather than an application HTTP parser. Bind `127.0.0.1:0` before
  opening the URL. Require exact callback path and Host, GET origin-form requests,
  one state and one code or error; reject duplicate/malformed/wrong-state requests.
  Bound headers to 16, the HTTP buffer to 8192 bytes and URI to 4096 bytes. Each
  connection has a three-second budget/two-second header timeout, at most 16 attempts
  and a five-minute overall callback timeout. The timeout durations are configured;
  cancellation/request-budget behavior was exercised, not a five-minute wall run.
- ASHPD 0.12.3 opens the external browser only after an explicit native Accounts
  action. No URL, authorization code or token enters a UI diagnostic. Cancel closes
  the pending listener. The completed flow consumes the code once and closes the
  listener before token exchange. Callback responses are static text with no-store,
  no-referrer and restrictive CSP headers.
- Google fixes its official authorization/token endpoints, requests the full Gmail
  scope and offline access/consent, and defaults to XOAUTH2. Microsoft fixes its
  common v2 endpoints and IMAP/SMTP/offline-access scopes. Custom OAuth requires
  explicit HTTPS endpoints, scopes and SASL. Preset endpoints cannot be overridden.
  Endpoint/scope/client input is bounded. Only bearer access tokens are accepted;
  a reported reduced scope set cannot silently authorize missing mail permissions.
- `auth::Session` shares one refresh mutex per account/reference across IMAP and
  SMTP. OAuth credentials carry an extra SHA-256 context attribute derived from
  their public client/provider/endpoint/scope metadata. Changing that metadata
  cannot send the old refresh token to a new client or issuer. Password keys keep
  their previous attributes. Unbound old refresh items require new authorization.
- Access tokens stay in redacted, zeroizing memory, with a 60-second expiry margin.
  Missing expiry means no timed reuse. Cached tokens still require an existing,
  unlocked encrypted keyring item. Refresh rotates the encrypted token **before**
  publishing access. A failed rotation write blocks reuse. Confirmed invalid_grant
  removes only that bound revoked credential and stops further refresh attempts;
  a successful foreground authorization clears the blocked state. Cancellation or
  an unknown refresh response can require later reauthorization; no success is
  inferred from a request merely having started.
- Accounts exposes Unlock/Connect/Cancel for either incoming or distinct outgoing
  auth. IMAP and SMTP resolve credentials through the same session; SASL still
  respects server capabilities and mandatory TLS. SMTP supports XOAUTH2, not
  OAUTHBEARER; IMAP supports both where advertised. There is no password downgrade.
- Quit cancels pending authorization and waits for its completion, including the
  bounded encrypted write after new tokens are issued, before closing the store.
  No background keyring constructor, automatic browser prompt, startup refresh or
  automatic outbox draining is introduced. These are still P04/P08 follow-ups.

## Development and protocol checks

Pinned nightly Cranelift/Wild environment, four existing SpiderMonkey LLVM
exceptions unchanged. `nix develop --command bash ci/check.sh` passed strict
workspace Clippy, formatting/lint tools and **85 workspace tests plus seven isolated
Servo child invocations**. The native debug app also built successfully. See
[development-check.log](artifacts/p05-oauth/development-check.log).

The new local HTTPS/loopback tests cover:

- A real S256 challenge/verifier exchange, public-client form, no client secret or
  Basic header, issued access/refresh tokens, expiry and refresh rotation.
- Wrong state, duplicate state/code, wrong path/Host/method, denial, cancellation,
  exhausted callback attempts and listener closure after completion.
- Token endpoint redirect refusal with a separate untouched loopback observer,
  oversized response rejection, typed invalid_grant and redacted error/Grant Debug.
- SMTP authenticating only with advertised XOAUTH2 over verified TLS, with no
  password fallback, and exactly the same frozen DATA bytes as the outbox original.

## Private encrypted-backend acceptance

Prebuild the `oauth` and `credentials` test executables in the normal development
shell, then pass their Cargo-reported paths as `MAILSTRONAUT_OAUTH_FIXTURE` and
`MAILSTRONAUT_CREDENTIAL_FIXTURE` to `experiments/p02-accounts/credentials.sh`
under `nix develop .#gui-test`. No Cargo runs in the GUI environment when these
paths are supplied, avoiding native build-script fingerprint churn.

[private-keyrings.log](artifacts/p05-oauth/private-keyrings.log) records two fresh,
separate project-local buses/XDG roots/real encrypted GNOME keyrings. Each lifecycle
intentionally ends with its private collection locked. No service activation or
user-session prompter is available, and no user bus/keyring is contacted.

The OAuth lifecycle passed: encrypted authorization, shared incoming/outgoing
refresh once, rotation persisted before both callers use access, restart using the
rotated token, retaining an omitted refresh replacement, changed-client isolation,
revocation removal/no retries, foreground reconnection, and refusal of a cached
access token while the keyring is locked. The independent password/purpose-isolation
lifecycle also passed. Both unavailable-service checks and persisted-ciphertext
marker checks passed; no plaintext fallback was created.

## Native desktop integration

The existing composer harness accepts `MAILSTRONAUT_COMPOSE_OAUTH=1`. Its prebuilt
OAuth fixture owns a **private mock OpenURI portal** plus a synthetic HTTPS IdP;
the app uses its real ASHPD request and production OAuth implementation. The mock
accepts only its own localhost public client/PKCE URL and returns a synthetic
callback. This is test scaffolding, not a real browser or COSMIC portal acceptance.

The [native run](artifacts/p05-oauth/native-oauth.log) passed: select account,
unlock, click Connect in browser, persist the scoped refresh grant, create/edit a
draft, close before its autosave delay, reopen/recover the draft, unlock and send.
The new process used the encrypted refresh token, rotated it before SMTP, and did
not open the portal again. The local SMTP fixture accepted exactly one XOAUTH2 DATA,
with no Bcc header and unchanged frozen MIME/Message-ID. Offline light-mode restart
preserved accepted state/attempt identity without another submission. The paired
OAuth keyring/unavailable-service tests also passed in that same harness invocation.
See [portal receipt](artifacts/p05-oauth/native-portal.log),
[authorized Accounts](artifacts/p05-oauth/native-account-authorized.png) and
[offline accepted outbox](artifacts/p05-oauth/native-offline-outbox.png).

Only X11/Xvfb at 100% was exercised. Actual browser opening, portal denial/revocation,
WM close during pending consent/rotation, real COSMIC/Wayland, keyboard/screen-reader,
Flatpak callbacks and suspend/clock-change acceptance remain open. Access-cache
resume invalidation belongs to P08; the current cache uses process monotonic time.
