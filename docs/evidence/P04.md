# P04 receiving and native inbox slice

2026-10-29, x86_64-linux; based on `e4535db`, implementation/evidence committed
together. P04 and the complete email client remain incomplete.

## Implemented path

- `async-imap` 0.12.0 over `tokio-rustls` 0.26.6 / Rustls 0.23.46, native
  certificate roots plus bounded explicit CA files. Required STARTTLS never sends
  authentication first and has no plaintext or invalid-certificate fallback.
- Advertised SASL PLAIN, password LOGIN fallback, XOAUTH2 and OAUTHBEARER. OAuth
  access tokens can be supplied to this adapter; browser authorization and refresh
  are not yet implemented. Static redacted errors discard server diagnostics.
- Explicit Ring builders for mail TLS; the renderer selects Ring before starting
  Servo threads, resolving the combined Ring/AWS-LC process-default ambiguity.
- Compile-time `log` debug/trace caps prevent async-imap's wire trace from exposing
  LOGIN/SASL payloads or complete mail responses, even with verbose runtime logging.
- Opaque ASCII/modified-UTF-7 LIST names and SPECIAL-USE attributes, SELECT,
  closed-range UID SEARCH, batches of at most 50 metadata records, and preflighted
  `BODY.PEEK[]` originals. No sequence number becomes a persistent identity.
- Core sync pages scan at most 128 UID values and download at most 16 MiB serially.
  Each original respects the configured size cap and the store's 8 MiB ceiling.
  The recent-date filter affects new body downloads, not the unfiltered SEARCH
  snapshot used to remove expunged memberships. Existing UIDs update flags without
  downloading bodies again; read-cleared history never returns to false.
- Paging positions include local folder identity, UIDVALIDITY and an exclusive
  UID upper bound. An old namespace restarts from SELECT's UIDNEXT. A cursor is
  returned after preceding local commits; no persistent sync cursor is claimed.
- Native libcosmic Inbox with account badges, unread indicators, extracted
  previews, keyset-paged cached rows and a selectable text reader. Four account
  jobs may run concurrently; each currently has one foreground connection.
  Configuration generations and read-request generations discard stale UI results.
  Mail contents in result events have redacted Debug implementations.
- Explicit incoming endpoints override verified Google/iCloud defaults. The
  sources are [Google's protocol settings](https://developers.google.com/workspace/gmail/imap/imap-smtp)
  and [Apple's settings](https://support.apple.com/en-ie/102525). These are endpoint
  presets, not live provider-login acceptance.

## Local development acceptance

All Rust commands used the pinned `nix develop` shell, Cranelift/Wild development
settings, the existing four LLVM FFI overrides and project-local target/cache.
The full runtime tests used the existing project-local headless GL environment.

```sh
cargo fmt --all
bash ci/check.sh
cargo build -p mailstronaut --all-features --locked --offline
```

Formatting, Nix formatting, actionlint, ShellCheck and strict workspace Clippy
passed. **65 workspace tests passed**, plus seven isolated Servo child invocations;
three explicit fixture tests were ignored in the ordinary suite. The test/build
log is [workspace-check.log](artifacts/p04-inbox/workspace-check.log).

The nine ordinary IMAP tests cover valid implicit/STARTTLS, untrusted/expired/wrong
hostname certificates withholding credentials, missing STARTTLS, advertised and
missing OAuth mechanisms, live handshake cancellation, UID gaps, exact wire names,
PEEK/no STORE, preflight size rejection, repeated-page idempotence, offline worker
restart, stale-generation cursors and wire-log suppression with an INFO positive
control. The expired localhost certificate uses a fixed 2020 validity interval;
all fixture certificates/keys are public synthetic test material.

The initial combined runtime gate exposed the Rustls provider panic described
above. The passing gate includes the explicit provider selection and all existing
renderer resource/script positive and negative controls. It does not broaden their
security acceptance.

## Private GUI acceptance

The prebuilt application and `imap_tls` fixture executable were passed to:

```sh
nix develop .#gui-test --command bash experiments/p02-accounts/credentials.sh
```

with `MAILSTRONAUT_INBOX_GUI_BINARY` and `MAILSTRONAUT_IMAP_FIXTURE` selecting those
binaries. The harness creates a private display, XDG tree, D-Bus and encrypted
GNOME Keyring; no user bus, credentials or mail servers are contacted.

The GUI unlocked that keyring, fetched two synthetic UID copies, displayed their
single canonical inbox row and copied the complete native body. Then it stopped
the application and loopback server, restarted offline in light mode and copied
the same verified cached body. Independent SQLite inspection confirmed UID flags
`(1001, unread)` and `(1003, read)`, plus exactly one canonical message. Opening
did not issue STORE. The two private keyring acceptance tests also passed.

See [dark online reader](artifacts/p04-inbox/reader-dark.png),
[light offline reader](artifacts/p04-inbox/reader-offline-light.png),
[GUI log](artifacts/p04-inbox/gui.log) and
[server receipt](artifacts/p04-inbox/server.log). Screenshots were visually inspected.
This covers Xvfb/X11 at 100%, not a real COSMIC user-session accessibility test.

## Remaining acceptance and resource limits

- The corrected vendor hash was built successfully; vendor output:
  `/nix/store/iy709shf20lic1vxz06h11i5nqqmdjs8-mailstronaut-0.1.0-vendor`, hash
  `sha256-0rK2DjxX5E0FLSbrRpO7/FxBQE5URhOEn2gJR9t2PaQ=`.
  **No new full Nix release/package gate or installed smoke is claimed here.**
- The connection has a 32 MiB received-byte cap, 30-second finite-operation
  timeout, bounded batches and cancellation. Upstream async-imap may preallocate
  for a declared literal before reading it, with its own 512 MiB buffer ceiling.
  The byte adapter does not lower that allocation ceiling. Hostile-server memory
  measurements and stronger parser allocation bounds remain open.
- Cache coverage is deliberately partial and visible. Oversized/old/unsupported
  messages are counted as omitted; metadata-only placeholder rows, full folder
  navigation, attachment-on-demand, persistent sync checkpoints, IDLE, polling,
  reconnect/backoff/resume and progressive per-account events remain unfinished.
- UTF-8 mailbox negotiation and display decoding are not implemented. Unsupported
  raw UTF-8 names are rejected; no lossy name is sent to a server.
- OAuth authorization/refresh, SMTP, drafts, read/star/move actions, search,
  conversations, reminders, classifier and background lifecycle remain pending.
  Opening currently preserves read state. No live Google/iCloud/institution login,
  Dovecot, CI, current-source Flatpak, large-folder/performance or AT-SPI acceptance
  is claimed. Arbitrary email HTML remains disabled in the Servo adapter; the
  native reader uses inert text extraction from the existing MIME library.
