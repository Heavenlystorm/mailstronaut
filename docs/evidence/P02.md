# P02 partial implementation evidence (2026-10-27)

P02 remains incomplete. Native configuration evaluation, a bounded same-binary
helper and `config init/check` are implemented. The subsequent
[account setup slice](P02-accounts.md) adds native startup/last-valid reload and
foreground credential storage, with private native Secret Service acceptance.
Complete cross-field validation, Home Manager activation and Flatpak portal
integration remain open. No real mail or secrets were used.

## Schema and evaluator

The evaluator is Snix `f393b22aa9b8e0e74c9e8d67f15454409299e510`, with Serde
1.0.228 and vendor hash `sha256-5vjUm3KUaciznlUYSKFhgjyzG1ZNTArKREA0OyPdu4Q=`.
Native Nix authentication deserializes through a strict typed intermediate map:
the pinned Snix `deserialize_any` path formats strings with quotes, preventing
Serde's internal-tag visitor from recognizing `kind`. Typed fields avoid that
path; serialization retains the tagged schema. No evaluator fork, host Nix
executable, imported Nixpkgs or alternative configuration format is used.

Synthetic tests exercise the checked-in example, documented Google/iCloud/manual
accounts, custom OAuth metadata, let/references/lists/conditionals, unknown keys,
invalid types, unsupported schema and hybrid/incomplete authentication fields.
These are configuration tests, not evidence of provider authentication support.
Full endpoint/CA and account-change validation still needs completion.

## Helper and CLI

The parent runs the installed executable with a private flag before graphics
initialization. Source travels over stdin, bounded to 256 KiB; typed result IPC
is bounded to 1 MiB. The child runs the existing pure strict evaluator, discards
stderr (including `builtins.trace`) and suppresses panic diagnostics. It imposes
1 GiB address-space, 2/3 second soft/hard CPU and zero core-dump limits using safe
rustix APIs. The parent bounds the entire exchange to two seconds and kills and
waits for the child on cancellation, timeout and transport failure. Task-abort
cleanup uses Tokio's kill-on-drop fallback and requires its runtime to stay alive;
explicit token cancellation is the tested path.

Actual-binary integration tests run with an empty PATH and no display/session
variables. They verify pure expressions, redacted failures, rejected readFile,
getEnv, import and fetchurl attempts, expanded output limits, recursive evaluation
timeout and cancellation of an observed live child. During the live-child test,
`/proc/<pid>/limits` confirms the configured memory/CPU/core limits; its PID is
absent after awaited cancellation. These observations establish configured kernel
limits and process cleanup, not a benchmark of allocation or CPU exhaustion.

`config init` writes a private native Nix file atomically without replacing an
existing file or managed symlink. Tests verify directory/file permissions,
non-overwrite behavior and paths containing spaces. `config check --path FILE`
uses the bounded helper; errors omit source and credential-like fixture text.
Managed editing, last-valid reload and normal application startup are not wired.

One warm development run of `time -v target/debug/mailstronaut config check
--path examples/config.nix` completed in 0.02 s with 34,604 KiB maximum RSS as
reported by GNU time for the command and its child. This single local observation
does not characterize GUI memory, cold startup or worst-case evaluator inputs.

## Validation boundaries

`CARGO_BUILD_JOBS=2 nix develop --command bash ci/check.sh` passed formatting,
actionlint, shellcheck, strict workspace Clippy and all 16 current tests with the
pinned Cranelift/Wild development shell. The three actual-binary integration tests
passed again after the final invalid-type additions. Stable LLVM
`nix flake check --no-update-lock-file --print-build-logs --cores 2 --max-jobs 1`
also passed, including strict Clippy and all 16 release-profile tests, on
x86_64-linux. `nix build --no-update-lock-file --cores 2 --max-jobs 1` reused the
verified package at
`/nix/store/a2vvr1cvqg9bih2kks84pk0k8q665xp7-mailstronaut-0.1.0`.
The installed wrapper passed `--version` and `config check --path
examples/config.nix` without display or session variables. aarch64 was omitted.

Native Secret Service, Flatpak Secret portal, disposable Home Manager linking,
live login, configuration reload and account disable/purge acceptance have not
been tested. No remote CI run or user configuration activation is claimed.
