# P09 quoted and superseded requests

Policy 3 excludes inline double-quoted spans and clauses explicitly attributed
to older forms or instructions. A quoted imperative cannot create an action
or deadline on its own. A separate current obligation in the same message still
gets its deadline. The surviving evidence range points into the untouched body.

The rule tests exercise English, French and Italian, including punctuation
inside quotes, older instructions followed by a real request, and a quoted
attachment name in a current instruction. The pinned local workspace passed
strict Clippy and 331 tests with 27 ignored. In the private native Wayland
walkthrough, the synthetic textbook example and copied form produced neither
an automatic deadline nor a priority result. The current request in a mixed
message produced one deadline. Automatic analysis left all three messages
unread before any original was opened. The same run passed date-only and timed
corrections and the existing priority and credential checks.

One earlier local walkthrough timed out because the synthetic bulk delivery
landed during a watch reconnect following a restart. The fixture now explicitly
wakes sync for the bulk and contextual phases. The separate automatic new
delivery check continues to exercise arrival without a sync button click.

This is bounded rule behavior for explicit quotation and attribution. General
recipient attribution, implied obligations and model accuracy remain open.
The historical NLI harness reads the exact policy-2 Git revision and its
registered source hash, leaving its failed held-out result reproducible.
The current Flatpak source archives were regenerated against the same vendor
input.
