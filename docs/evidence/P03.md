# P03 evidence (partial, 2026-10-27)

The provisional `rusqlite_migration` schema enables foreign keys, WAL and FTS5.
`Store` opens a caller-supplied private data directory; it is not an XDG locator or
a bounded database worker. Ingestion takes an SQLite IMMEDIATE transaction before
writing a SHA-256-addressed original through a private sibling temporary file,
syncing the file and directory before committing its message reference. Orphan
collection takes the same writer lock and only removes unreferenced regular files
whose names are 64 lowercase hexadecimal digits. Existing destinations are checked
for regular-file type and exact content with bounded buffers; corruption is rejected.
A failed insert may leave a collectible orphan. `clear_rebuildable_indexes` deletes
only FTS entries and preserves message and user-owned state; it does not evict bodies.

Each ingest currently creates a distinct message row, including repeated content
in one account. Blob storage is shared across accounts, but canonical account-local
message deduplication needs provider or Message-ID metadata and remains future work.
Drafts and outbox content are inline; attachment blob references are not implemented.

Local `nix develop --command bash ci/check.sh` passed on x86_64-linux: six
synthetic store tests passed along with the workspace checks. Local `nix flake check
--no-update-lock-file --print-build-logs` also passed on x86_64-linux, including
release-profile tests; the package output was `/nix/store/y4gkg0x2qkp5rds1wxdikig3gd9shcb6-mailstronaut-0.1.0`.
The tests cover reopen and shared blobs, separate-handle writer-lock exclusion,
failed inserts and orphan collection, corrupt and symlink destinations, unrelated
file retention, foreign keys and index-clear durable-state retention. These are not
crash-injection or adversarial filesystem race tests.

Schema completeness and immutable IDs, account-local canonical identity, attachment
references, UID reconciliation, upgrade/backup and migration rollback, MIME/threading,
and a dedicated bounded store worker remain open. No 100k benchmark, CI, GUI,
live account, or distribution acceptance is claimed. P03 remains unchecked.

## Focused MIME projection slice (2026-10-27)

The MIME slice, originally developed on base `2a92a50` and cherry-picked onto
`09b340a`, uses `mail-parser` 1.0.0 with `full_encoding`.
Its published manifest requires Rust 1.98, so the workspace lower bound was raised
from 1.97; the pinned Nix shell reports rustc 1.99.0. The parser's 1.0 source was
inspected for limits, checked text decoding, part flags, message-local attachment
roles and offsets. The projection retains a maximum 8 MiB original, limits parsing
to 256 parts and depth 32, retains at most 64 root attachment descriptors, and
bounds each decoded body to 256 KiB. Oversized encoded body parts are omitted and
flagged; attachment content is not eagerly copied. Encoded nested messages are
not recursively decoded. CID resolution is message-local and refuses duplicates
or incomplete attachment/part sets. Encrypted MIME containers and an inline OpenPGP marker within the first 4096
decoded characters of a plain-text part suppress all body and preview extraction;
this bounded marker check is not a complete encrypted-mail detector. HTML is untrusted and still needs the separate rendering policy.
The source revision is the original-message SHA-256; previews explicitly record
`Extracted` provenance, with a reserved generated source for future use. CID keys
reject empty, non-ASCII, whitespace, control and angle-bracket characters; this
conservative policy may reject valid uncommon IDs. Parser flags report structural degradation and part/depth truncation;
checked decoding reports errors for extracted bodies. Attachment payload decoding
and validation remain future work.

Local focused checks on x86_64-linux, with `CARGO_BUILD_JOBS=2`, passed:

```sh
nix develop --command bash -c 'cargo fmt --all && cargo clippy -p mailstronaut-core --all-targets -- -D warnings && cargo test -p mailstronaut-core --all-targets && cargo fmt --all -- --check'
```

Ten synthetic MIME tests cover alternatives, decoded Unicode headers/addresses,
non-UTF8 and transfer encodings, HTML preview, malformed and missing fields,
forwarded mail and original-buffer attachment offsets, scoped, invalid and duplicate CIDs, attachment/part/input/body limits, and
encrypted MIME and inline OpenPGP stubs, and preview provenance. Six existing store tests also passed. No full flake gate,
remote CI, GUI, live-account or distribution acceptance is claimed by this slice;
P03 checklist rows remain open.
