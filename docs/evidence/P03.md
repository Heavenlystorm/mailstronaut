# P03 evidence (partial, 2026-10-27)

The provisional `rusqlite_migration` schema enables foreign keys, WAL and FTS5.
`Store` opens a caller-supplied private data directory; it is not an XDG locator or
a bounded database worker. Ingestion takes an SQLite IMMEDIATE transaction before
writing a SHA-256-addressed original through a private sibling temporary file,
syncing the file and directory before committing its message reference. Orphan
collection takes the same writer lock and only removes unreferenced regular files
whose names are 64 lowercase hexadecimal digits. Existing destinations are checked
for regular-file type and exact content with bounded buffers; corruption is rejected.
A failed insert may leave a collectible orphan. `clear_rebuildable_indexes` deletes
only FTS entries and preserves message and user-owned state; it does not evict bodies.

Each ingest currently creates a distinct message row, including repeated content
in one account. Blob storage is shared across accounts, but canonical account-local
message deduplication needs provider or Message-ID metadata and remains future work.
Drafts and outbox content are inline; attachment blob references are not implemented.

Local `nix develop --command bash ci/check.sh` passed on x86_64-linux: six
synthetic store tests passed along with the workspace checks. Local `nix flake check
--no-update-lock-file --print-build-logs` also passed on x86_64-linux, including
release-profile tests; the package output was `/nix/store/y4gkg0x2qkp5rds1wxdikig3gd9shcb6-mailstronaut-0.1.0`.
The tests cover reopen and shared blobs, separate-handle writer-lock exclusion,
failed inserts and orphan collection, corrupt and symlink destinations, unrelated
file retention, foreign keys and index-clear durable-state retention. These are not
crash-injection or adversarial filesystem race tests.

Schema completeness and immutable IDs, account-local canonical identity, attachment
references, UID reconciliation, upgrade/backup and migration rollback, MIME/threading,
and a dedicated bounded store worker remain open. No 100k benchmark, CI, GUI,
live account, or distribution acceptance is claimed. P03 remains unchecked.

## Focused MIME projection slice (2026-10-27)

The MIME slice, originally developed on base `2a92a50` and cherry-picked onto
`09b340a`, uses `mail-parser` 1.0.0 with `full_encoding`.
Its published manifest requires Rust 1.98, so the workspace lower bound was raised
from 1.97. Initial checks used Rust 1.99.0; the hardening follow-up uses the pinned
1.101.0-nightly Cranelift/Wild development shell. The parser's 1.0 source was
inspected for limits, checked text decoding, part flags, message-local attachment
roles and offsets. The projection retains a maximum 8 MiB original, limits parsing
to 256 parts and depth 32, retains at most 64 root attachment descriptors, and
bounds each decoded body to 256 KiB. Oversized encoded body parts are omitted and
flagged; attachment content is not eagerly copied. Encoded nested messages are
not recursively decoded. CID resolution is message-local and refuses duplicates
or incomplete attachment/part sets. Encrypted MIME containers and inline OpenPGP
markers suppress all body and preview extraction. Marker inspection uses the
parser's bounded transfer/charset decoding over the 256 KiB body budget plus a
marker-length overlap; it includes implied text/plain without a Content-Type.
This is not a complete encrypted-mail detector. HTML is untrusted and still needs
the separate rendering policy.
The source revision is the original-message SHA-256; previews explicitly record
`Extracted` provenance, with a reserved generated source for future use. CID keys
reject empty, non-ASCII, whitespace, control and angle-bracket characters; this
conservative policy may reject valid uncommon IDs. Parser flags report structural
degradation and part/depth truncation;
checked decoding reports errors for extracted bodies. Attachment payload decoding
and validation remain future work.

Local focused checks on x86_64-linux, with `CARGO_BUILD_JOBS=2`, passed:

```sh
nix develop --command bash -c 'cargo fmt --all && cargo clippy -p mailstronaut-core --all-targets -- -D warnings && cargo test -p mailstronaut-core --all-targets && cargo fmt --all -- --check'
```

Eleven synthetic MIME tests cover alternatives, decoded Unicode headers/addresses,
non-UTF8 and transfer encodings, HTML preview, malformed and missing fields,
forwarded mail and original-buffer attachment offsets, scoped, invalid and duplicate
CIDs, attachment/part/input/body limits, encrypted MIME and inline OpenPGP stubs,
and preview provenance. A parent regression reproduced missing encrypted status
for headerless armor and exercised armor beyond the old 4096-character prefix;
the bounded detection now covers both. Six existing store tests also passed.

After integration, `CARGO_BUILD_JOBS=2 nix develop --command bash ci/check.sh`
passed formatting, actionlint, shellcheck, strict workspace Clippy and all 27
tests (11 MIME, six store and ten configuration/CLI/helper tests). The new
headerless/long-preamble regression failed before the detection fix and passed
after it. The current MIME revision has not passed a full Nix release build;
that integration gate will run with the next renderer dependency changes to
avoid duplicating expensive package builds. No remote CI, GUI, live-account or
distribution acceptance is claimed. P03 checklist rows remain open.

Renderer integration subsequently aligned rusqlite to 0.38.0 and
rusqlite_migration to 2.4.1 to share Servo 0.7's native SQLite dependency. All six
store and eleven MIME tests passed in the focused mixed-backend development
checks. The earlier Nix release artifact predates this binding change; acceptance
of the new graph still requires the combined renderer/package gate.

## Bounded attachment descriptors and revisions

At `3ec624c`, all 17 tests in the MIME integration target passed in the
pinned Linux Nix development environment:

```sh
cargo test --locked --offline -p mailstronaut-core --test mime
```

- `alternatives_headers_and_encodings` reads an ISO-8859-1 quoted-printable
  original and its base64 UTF-8 HTML alternative. The forwarded-message test
  keeps nested text outside the parent body and verifies original attachment offsets.
- `bounds_encryption_and_malformed`, the inline OpenPGP tests and the part/count
  limits exercise malformed transfer encoding, missing headers, encrypted
  alternatives, and bounded body/input/attachment handling.
- `oversized_attachment_fields_leave_payloads_and_other_cids_available` checks
  that an oversized filename, media type or Content-ID is omitted as a whole.
  Exact decoded bytes remain available by the original attachment index. Other
  valid message-local CID images still decode. A dedicated flag distinguishes
  omitted attachment metadata from truncated routing headers.
- `changing_only_an_attachment_changes_the_original_and_preview_revision`
  holds the body text constant, changes only attachment bytes, and checks that
  both revisions change. The file list retains an inline-disposition PDF with a
  Content-ID and explicit extraction returns its decoded bytes by index.
  Preview provenance remains `Extracted`.

These fixtures use the original 8 MiB message limit, 256-part and 32-level
parser limits, 64 attachment descriptors and 256 KiB body limit. Attachment
header fields use the same 4096-byte ceiling as root headers.

A separate private Wayland run opened a synthetic “Meeting agenda” message
with one inline PDF and a Content-ID. The native reader displayed
`agenda.pdf`, `14 B` and `application/pdf` above its text. This observation
covers file visibility. The MIME tests above check the returned bytes.
