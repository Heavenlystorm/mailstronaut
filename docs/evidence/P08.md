# P08 — Foreground reminder slice

P08 remains open. This slice adds durable reminders and native controls while the
application is open. Background lifetime, desktop activation and full COSMIC
notification acceptance are separate work.

The native reader's **Remind** control targets its exact account and original
message. The Reminders page offers an elapsed hour, today's configured evening,
tomorrow's configured morning, and libcosmic's existing calendar with an HH:MM
field. Chrono/Chrono TZ resolve civil time: nonexistent DST times are rejected;
ambiguous times choose the first still-future occurrence. The selected UTC instant
and original IANA timezone persist. All reminders remain independent of Seen and
priority history. A pending reminder stays scheduled after opening its message.

Schema 6 preserves legacy rows, binding only one unambiguous record per original;
unbound duplicates and missing legacy targets are retained. Creation is create-only,
rescheduling/cancellation use compare-and-swap generations, and every desktop
handoff has an attempt token. Late edits, actions and acknowledgments cannot mutate
a newer generation or another account. Missing originals become unavailable and
are never replaced by a same-subject message. The visible list is bounded to 100;
the scheduler queries the earliest pending record independently of that page.

A bounded foreground Tokio loop requeries at most 30 seconds apart, or at an
upcoming due instant. It processes at most four notifications per pass. This is
not backlog-summary coalescing or an explicit resume/clock-change watcher yet.
Notification IDs are allocated before handoff and retained through rescheduling
and exclusive-owner restart recovery. Removal requests survive cancellation and
rescheduling, including when new notifications are disabled. Failures retain an
entry for explicit retry; muted notifications leave overdue entries visible.

ASHPD uses the notification portal only in this slice. No native fallback is
implemented, and portal refusal is not bypassed. The portal proxy and action
stream live entirely inside a bounded Tokio task: the native test found and fixed
a shutdown panic caused by dropping a zbus object on the UI thread. Generic
notification text is the default. `notifications.showPreview` explicitly enables
bounded extracted subject/body text. Mail is never used as markup or commands.
Open, Remind again and Dismiss resolve a stable local ID and current generation;
action reception currently requires the application to remain running. Desktop
acceptance is not evidence that the user saw a notification.

## Local acceptance

Pinned `nix develop` checks run formatting, Nix formatting, ShellCheck, Actionlint,
strict workspace Clippy and all workspace tests, followed by the native build.
The focused tests cover account/generation fencing, invalid selections, DST
calendar-day presets and folds/gaps, original deletion, migration preservation,
independent read history and exclusive-owner recovery. The suite passed **133 workspace tests plus seven isolated renderer children**.
[Development check log](artifacts/p08-foreground/development-check.log).
The native explicit-open/read-status regression also passed with the new Remind
control present: [regression log](artifacts/p08-foreground/explicit-open-regression.log).

The [private portal test](artifacts/p08-foreground/private-portal.log) exercises the
real ASHPD D-Bus serialization and action stream against a synthetic service:

- A claimed-but-unsubmitted delivery recovers on exclusive restart.
- An accepted delivery whose DB acknowledgment is absent is retried using the
  same replaceable ID. These are simulated durable crash windows, not SIGKILL
  injection or proof of a desktop server's actual replacement behavior.
- Current actions resolve the correct original; malformed/stale/foreign actions
  cannot resolve another reminder. Hidden-preview receipts contain no synthetic
  mail markers; an explicit preview positive control does contain them.
- Mute retains pending entries; refusal produces a visible failed record without
  automatic resubmission; explicit retry succeeds; cancellation withdraws it even
  with notifications disabled.

The [private native X11/Xvfb test](artifacts/p08-foreground/native-gui.log) clicks the
one-hour/tomorrow/custom controls, verifies persisted UTC/timezone/generations,
opens the exact message, marks it unread without cancelling its reminder, closes
normally, restarts offline, opens that reminder explicitly and cancels it. It
creates no draft or outbox item. Screenshots: [editor](artifacts/p08-foreground/editor.png),
[custom](artifacts/p08-foreground/custom.png),
[offline](artifacts/p08-foreground/offline.png),
[cancelled](artifacts/p08-foreground/cancelled.png).

## In-app opening without a desktop receipt

A follow-up separates the native list's Open action from notification-ID lookup.
It resolves the exact original account/message and checks reminder ID/generation,
so legacy/unsubmitted reminders can open before they have a desktop receipt.
Desktop signals retain their stricter notification-ID lookup. A new behavior test
verifies no-receipt opening, disabled-account rejection and stale ID/generation
rejection without changing the pending reminder. Strict pinned app Clippy and
all **134 workspace tests plus seven renderer children** passed, followed by the
native build and the full reminder GUI/restart/cancellation regression.
[Checks](artifacts/p08-foreground/original-open-check.log),
[native regression](artifacts/p08-foreground/original-open-native.log).
The coordinated release gate already in flight targets the preceding slice; it
does not yet validate this follow-up.
