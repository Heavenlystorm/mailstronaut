# P07 — Bounded native compose and durable SMTP prototype

P07 remains **incomplete**. This implements plain-text composition and password
submission alongside the P04 receiving prototype. It does not establish the full
Thunderbird replacement, provider, mailbox-action or distribution acceptance.
All mail, accounts, recipients, certificates and passwords below are synthetic.

## Implemented behavior

- Native libcosmic account/alias selection, To/Cc/Bcc, subject and text editor.
  Lettre 0.11.23 owns address parsing, MIME/Unicode header encoding and SMTP.
  Invalid/oversized fields are rejected before queueing; incomplete drafts may be
  saved. Bcc exists in the private envelope/draft, never visible MIME headers.
- Revisioned SQLite drafts autosave after 500ms. Stale saves cannot replace newer
  edits, nor recreate a queued draft. Switching drafts waits for saving the current
  edit; failures preserve the editor. Normal window close flushes the latest edit,
  completes submission bookkeeping and joins the dedicated storage owner before exit.
- Schema 3 preserves legacy draft/outbox payloads, backs up schema 1/2 before upgrade,
  and adds account-scoped drafts/outbox, revision/closed state, attempt tokens and
  uncertainty history. One live application owner holds a kernel advisory profile
  lock before migration/recovery. This is not D-Bus activation or background support.
- Queueing freezes MIME, one Message-ID and a separate envelope transactionally.
  Hash-verified originals survive index clearing and orphan collection. Before any
  SMTP operation, a unique attempt token and `submitting` state commit to disk.
  Late callbacks cannot complete a newer attempt. Interrupted attempts recover as
  `delivery_unknown`; opening an independent integrity Store does not interrupt a
  live sender.
- SMTP uses lettre with Tokio/Rustls, native plus explicit CA roots, certificate and
  hostname validation, mandatory STARTTLS or implicit TLS and bounded operation
  times. There is no insecure mode or credential fallback. Password mechanisms and
  XOAUTH2 exist in the adapter; the foreground UI currently submits passwords only.
  Every send/retry requires an explicit foreground action. No outbox auto-drain runs.
- A positive DATA acknowledgment is terminal for SMTP. A definite refusal, invalid
  TLS, missing required capability and ambiguous connection loss have distinct
  durable results. Cancel/timeout after an attempt starts is conservatively unknown.
  Retrying preserves original bytes/Message-ID and requires explicit possible-
  duplicate consent if delivery was uncertain. A rejected/cancelled later attempt
  never erases earlier uncertainty. Definite failures can be edited as a new draft,
  atomically disabling the old sending intent; unknown deliveries cannot silently
  become unsent drafts.
- Gmail is recorded as provider-managed Sent auto-save; other accounts retain a
  separate pending Sent-copy state. No Sent APPEND/reconciliation implementation
  is claimed. Failure of a future Sent copy must never reopen SMTP submission.
- Mail-bearing UI events and compose data have redacted Debug implementations.
  Existing protocol trace suppression remains enabled. Synthetic GUI log checks
  found no cleartext credential marker; this is not a general logging audit.

## Checks and local artifacts

Pinned x86_64-linux development environment, nightly Cranelift/Wild with the four
existing SpiderMonkey LLVM exceptions:

```sh
nix develop --command bash ci/check.sh
nix develop --command cargo build -p mailstronaut --all-features --locked --offline
```

Strict workspace Clippy, formatting, Nix formatting, Actionlint, ShellCheck and
**81 workspace tests plus seven isolated Servo child invocations passed**.
The complete successful run is [development-check.log](artifacts/p07-compose/development-check.log).
This includes MIME/SMTP fixture integration, not only mocked state transitions:

- TLS and required STARTTLS; untrusted/wrong-host certificate and absent STARTTLS
  refuse before credentials or mail. Explicit DATA rejection differs from lost
  post-DATA acknowledgment; authentication refusal makes only one attempt.
- Recipient DATA equals the frozen original byte-for-byte, including final CRLF,
  dot-stuffing roundtrip, encoded Unicode, Bcc exclusion and retained Message-ID.
- SMTP outcomes commit through the real worker and survive restart without retry.
- Draft revision/closed fencing, account isolation, discarded UI waiters, schema-2
  backup/migration, exclusive profile ownership, stale attempts, ambiguous retry
  history, safe edit recovery and durable blob references.

`experiments/p07-compose/gui.sh` is invoked by the existing private Secret Service
harness. It creates a fresh project-local XDG profile, a private bus without service
activation, an encrypted synthetic keyring, Xvfb and one localhost TLS SMTP fixture.
The configured incoming host is deliberately invalid and synchronization is never
requested. No user bus, keyring, account or real relay is contacted.

Run with prebuilt app and the Cargo-produced `smtp` test executable:

```sh
MAILSTRONAUT_COMPOSE_GUI_BINARY="$PWD/target/debug/mailstronaut" \
MAILSTRONAUT_SMTP_FIXTURE=/absolute/path/to/smtp-test-executable \
MAILSTRONAUT_CREDENTIAL_FIXTURE=/absolute/path/to/credentials-test-executable \
nix develop .#gui-test --command bash experiments/p02-accounts/credentials.sh
# Repeat with MAILSTRONAUT_SMTP_DROP_ACK=1 for the unknown-delivery control.
```

Both normal-acknowledgment and lost-acknowledgment GUI runs passed. Each enters the
native fields, verifies local autosave, types a final edit and immediately clicks
the window close control before the debounce, verifies a normal exit and persisted
last edit, reopens/loads the draft, unlocks its private keyring and explicitly sends.
It then restarts offline in light mode, verifies terminal outbox state and compares
the received synthetic message with the private hash-addressed original. Both runs
also passed the two separate private credential-service acceptance tests.
The sender dropdown was rendered with configured primary/alias identities; actual
alias switching, keyboard-only compose and accessibility were not accepted here.

## Remaining acceptance

Attachments/portal selection, signatures, reply/reply-all/forward, Sent APPEND and
manual Sent reconciliation, Google/institutional OAuth onboarding/refresh, safe
mailbox actions/undo, automatic sync and notifications remain unimplemented.
Provider Sent auto-save is a configured policy, not a live Gmail verification.
The SMTP adapter rejects OAUTHBEARER because lettre exposes XOAUTH2 only.

No real mail has been sent. No live-provider, CI, Flatpak, full security or
accessibility acceptance is claimed here. Release acceptance above covers only
the recorded draft/SMTP commit; newer changes need their own gate. Development
checks and local GUI fixtures must not be substituted for those gates. The pinned
lettre parser checks response bounds after reading a line; hostile-server allocation
limits are not fully established. P04 separately records async-imap's preallocation
limit. Untrusted email HTML remains excluded from the synthetic Servo renderer.
