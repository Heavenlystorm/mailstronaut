# P06 — Bounded account-local conversation prototype

Status: implemented native/offline prototype; **P06 remains incomplete**. This
slice uses real cached message identities, the pinned `mail-threading` 0.1.3
component and native libcosmic widgets. No real mailbox, sender or recipient was
used; arbitrary email HTML remains excluded from the synthetic Servo renderer.

## Behavior and ownership

- References, then an unambiguous In-Reply-To, connect messages within one configured
  account. Missing ancestors can connect siblings; identical subjects never merge
  mail. Duplicated Message-IDs preserve distinct originals; referenced duplicate
  IDs follow the pinned component's first-binding policy. Truncated routing headers
  cannot supply ancestry. Gmail-specific X-GM-THRID grouping is not implemented.
- Schema 5 stores normalized ancestry and stable account-local conversation/member
  identities. Insert/delete/routing/date triggers invalidate the derived revision;
  flag edits do not. Helpers receive immutable snapshots, and commits validate exact
  local-ID coverage, account ownership and the unchanged metadata revision.
- The oldest surviving member reserves its previous conversation identity before
  merges are considered. Merges keep the oldest eligible conversation ID and
  compress old aliases. A split retains each old identity only for the group with
  its oldest surviving member. Alias resolution is account-scoped and survives
  restart. Tests include simultaneous split/merge and removal of an old root.
- One inbox row represents one account-local conversation. Its latest inbox member
  supplies preview/open identity; unread/star aggregates use only inbox memberships.
  Cached Sent/Archive members participate in ancestry and the member selector. The
  selector includes the selected member plus at most 199 newest others and reports
  the cap. Full member paging remains open. Counts describe all current cached
  members, not a promise that the server history is fully downloaded.
- Selecting a member loads its own original/text. Reply actions capture the reader
  generation; read/star/undo capture generation, account and message identity.
  A cached ancestor outside Inbox has read-only flag controls in this prototype.
  Explicit Mark read changes only the selected inbox member; automatic marking
  on visible reading is not implemented yet.
- SQLite work stays on the dedicated owner. Grouping runs outside both UI and
  database threads, in a short-lived same-executable metadata-only child. There is
  no separate service or alternative threading implementation. Sync commits its
  page even if grouping fails; stale/missing grouping shows distinct flat messages.

## Grouping resource boundary

The library's recursive/deep-ancestry path requires containment. Input is capped
at 50,000 messages, 100,000 conservative message/identifier nodes and 32 MiB JSON;
output is capped at 4 MiB and must cover every input identity exactly once. No
subjects, recipients, bodies, credentials or database handle are supplied. Error
and Debug output is redacted; the parent discards child stderr.

Before reading stdin, the child applies address-space 1 GiB, CPU 5s soft/6s hard
and zero core-file limits. The parent enforces a 10s wall timeout, cancellation,
kill and wait/reaping. Resource limits are not a filesystem/network capability
sandbox. This process executes only the pinned Rust grouping code; no plugins or
commands are selected by mail content.

The real-executable [probe](../../experiments/p06-conversations/probe_helper.py)
observed all three limits before input and grouped 10,000 synthetic headers into
5,000 pairs in **0.216s**, with **75,780 KiB peak child RSS**, 1,141,119 request
bytes and 58,906 response bytes. See [receipt](artifacts/p06-conversations/helper-probe.json).
This is a single debug component measurement on this machine, not a cold-start,
large-inbox UI, end-to-end sync or worst-case performance result.

## Native offline acceptance

Use the normal Nix shell to prebuild the application, core worker and credential
fixtures. Set `MAILSTRONAUT_THREADS_GUI_BINARY`, `MAILSTRONAUT_THREADS_FIXTURE` and
`MAILSTRONAUT_CREDENTIAL_FIXTURE` to their exact executables, then run:

```sh
nix develop .#gui-test --command bash experiments/p02-accounts/credentials.sh
```

The [native script](../../experiments/p06-conversations/gui.sh) passed under private
X11/Xvfb at 100% scale. Two invalid-network configured accounts and five cached
synthetic messages produce three rows: two unrelated equal-subject conversations
and one three-member conversation containing a cached Sent ancestor. It copied
and checked each selected member's body, changed only the latest member's read
intention, selected/replied to the Sent parent with the right receiving identity
and ancestry, and confirmed ancestor flag editing was disabled. Normal close and
light-mode offline restart preserved grouping and the single pending flag. Opening
another account's identical RFC identifier copied its different body and prepared
its own reply identity. No mail was queued or sent. The private keyring lifecycle
and missing-service tests passed as well. [GUI log](artifacts/p06-conversations/native-gui.log).
